# CLAUDE.md

MobiumApp is the application under test for
[Mobium](https://github.com/mobiumdev/mobium): a React Native (Expo) app whose
only job is to be driven. Every screen is a **positive control** — a case that
can go wrong when a tool automates a mobile app, produced on demand so a check
can tell "handled" from "never saw it". See [README.md](README.md) for the
screens.

## Expo has changed

This is Expo SDK 57. Read the versioned docs at
https://docs.expo.dev/versions/v57.0.0/ before writing code; APIs and config
keys from older SDKs are often wrong here.

## Commands

```sh
npm install
npx tsc --noEmit                      # type check; the only static check there is

npx expo prebuild --platform ios      # generates ios/, which is not committed
npx expo run:ios --configuration Release --device <udid>

npx expo prebuild --platform android  # generates android/, not committed
npx expo run:android --variant release
```

Build **Release**, not debug: it bundles the JavaScript, so the installed app
needs no Metro server and a check script can drive it cold.

## Test IDs are a contract

Mobium's end-to-end checks drive this app by `testID` — `mobium-app.sh`,
`login.sh`, `dialogs.sh`, `obstruction.sh`, `web-actionability.sh`, `web-type.sh`, `gestures.sh`, `autowait.sh`, `keyboard.sh`,
`source.sh`, `clear-data.sh`, `crashes.sh`, `biometric.sh`, `zoom.sh`, `feed.sh`, `slider.sh`, `graybox.sh`, `graybox-edges.sh`, `graybox-hooks.sh`, `frames.sh` and `audio.sh` under `docs/checks/`
in the Mobium repository.

- **Never rename or remove a `testID`** without changing those checks in the
  same change. A rename here fails them there, and nothing in this repository
  will tell you.
- **Mind IDs that contain one another.** Mobium matches a hand-written
  `testid=` exactly first and then by case-insensitive substring, so a partial
  ID can match several elements. On a screen where a check writes IDs by hand —
  the Login Demo's fields, say — keep them from containing each other.
- Some IDs are built at runtime — `k + 'Btn'`, `'card' + n`, `id + 'Target'`,
  `id + 'Result'` — so search for the parts, not only the whole string.
- Keep the README's screen table in step with the IDs.

## Designing a screen

- **Every screen is a control for a specific failure**, and says on screen what
  it isolates. Where "nothing happened" is a possible answer, add a negative
  control that must not change — the Motion Demo's ignoring target, the
  Interruption Demo's lost draft — so a check can tell a real result from one
  that could not see.
- **The app reports its own outcome** in a visible line (`dialogOutcome`,
  `formState`, `storedCount`, …) rather than leaving a check to infer it.
- **Every `WebView` sets `webviewDebuggingEnabled`.** On iOS 16.4 and later a
  WKWebView is invisible to any debugger unless the app opts in; that is the
  reason this app exists.
- **Pages are inline HTML, never fetched**, so no check depends on a network or
  a domain. The one real link is `LINK_URL`, defined once.
- **Never real data.** The demo account is `mobium` / `hunter2`, shown on
  screen. Nothing personal, no real credentials, no real endpoints, and no
  analytics: the app is installed on people's phones.
- Anything platform-specific is stated on screen rather than approximated —
  `Alert.prompt` is iOS-only, so the Android button says so.

## Conventions

- American spelling in code, comments and docs.
- TypeScript throughout; `npx tsc --noEmit` must pass.
- `ios/` and `android/` are generated by `expo prebuild` and ignored; configure
  native behavior through `app.json` and Expo config plugins instead.
- **The app must stay signable with a free Apple ID**, which a personal team
  cannot do for Push Notifications. `plugins/withoutPushEntitlement.js` removes
  the `aps-environment` entitlement `expo-notifications` adds, and it must be
  listed **before** `expo-notifications` in `app.json`: entitlement mods run
  in reverse order, so listed after it, it runs first and is undone. After
  touching plugins, prebuild and check `ios/MobiumApp/MobiumApp.entitlements`
  has no `aps-environment`.
- The bundle identifier and Android package are `dev.mobium.mobiumapp`.
